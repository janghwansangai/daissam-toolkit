# 전체 화면 발표 도우미 · v0.20

다있쌤 확장과 함께 쓰는 로컬 앱입니다. 화면은 파일로 저장하거나 네트워크로 보내지 않습니다.

## 조작

- 시작: 메뉴 막대(macOS) 또는 작업 표시줄 트레이(Windows)의 ‘발표 시작’.
- 확대/축소: **Control + Option(Mac) / Alt(Windows) + 마우스 휠**, 1~4배.
- **발표 시작·종료는 `Control + Option/Alt + P`** — 앱이 켜져 있으면 발표 전에도 듣습니다.
- 단축키(발표 시작·종료·집중 모드·화면 조각·클립보드·핀 닫기·클릭 통과)는 사이드바 발표 탭 → `단축키 안내 · 바꾸기` 에서 바꿉니다. 맥과 윈도우를 따로 정하고, 운영체제가 이미 쓰는 조합은 고를 수 없습니다. 휠과 `Esc` 는 고정입니다.
- 원래 배율: **Esc**. 큰 포인터는 발표 종료까지 유지됩니다.
- 종료/복원: 트레이 또는 메뉴 막대의 ‘발표 종료’. 완전히 끄려면 ‘앱 종료’.
- 원래 화면이 계속 움직이는 실시간 확대입니다. 마우스 아래 원본 지점을 기준으로 확대 위치가 따라갑니다.

## 화면 조각 핀

화면의 한 부분을 잘라 늘 위에 뜨는 작은 창으로 붙여 둡니다. 메뉴(macOS 메뉴 막대 → `화면 조각 핀`, Windows 트레이)나 확장 사이드바의 발표 탭에서 열며, 발표 중에는 `Control + Option/Alt + S`로도 됩니다. 클립보드의 그림과 글도 붙일 수 있고(`+ V`), 한 번에 12개까지 띄웁니다.

핀 하나는 끌어서 옮기고, 휠로 크기를, `Command/Ctrl + 휠`로 투명도를 바꿉니다. 오른쪽 클릭 메뉴에 잘라내기·복사·바탕화면 저장·회전·좌우 뒤집기·원래대로·클릭 통과·접기·닫기가 모두 있습니다.

**조각 위에 그리기**: `✎` 단추나 `d` 키로 들어가면 핀 아래에 도구 줄이 붙는다. 나가는 길(`✓` · Return · Esc)은 **모두 그린 것을 남긴다** — 버리는 길을 따로 두지 않는 이유는, 애써 그려 놓고 Esc 한 번에 날리는 일이 실제로 나왔기 때문이다. 모두 지우려면 `⌫`. 그리는 도중에도 `⌘`(Windows `Ctrl`) 끌기로 핀을 옮길 수 있다. 고른 색은 칸을 덮지 않고 흰 테두리로만 표시한다. 펜·원·밑줄·모자이크·글자 다섯 가지, 색 6가지, 굵기와 글자 크기 3단계. 표시는 **그림 좌표**로 담기므로 핀을 키우거나 줄여도 같은 자리에 남는다. `✓`(Return)를 누르면 `flatten()` 이 표시를 그림에 구워 넣고 `source` 를 바꾼다 — 그래서 복사·저장·자르기·회전이 전부 그대로 따라온다. `↶`/`z` 되돌리기는 굽기 전까지만 듣는다. 모자이크는 그 자리 픽셀을 1/14 로 줄였다가 최근접으로 늘려 쓰며, 만들 때 한 번만 계산해 둔다.

**모퉁이로 다시 자르기**: `⛶` 단추나 `x` 키로 자르기 모드에 들어가면 네 모퉁이 손잡이와 삼등분 선이 뜹니다. 모퉁이를 끌어 범위를 정하고 Return/Enter 로 자릅니다. 안쪽을 끌면 범위를 옮기고, 바깥을 끌면 새로 잡습니다. Esc 는 자르기만 취소합니다. 자른 결과가 새 원본이 되고 회전 상태는 결과에 반영된 뒤 0 으로 돌아가므로, 이어서 또 자를 수 있습니다. macOS 는 CGImage 를 직접 잘라내고(`Pin.cut`) 회전도 CoreGraphics 로 처리해(`Pin.turned`) Retina 픽셀을 잃지 않습니다. Windows 는 `Bitmap.Clone` 과 `RotateFlip` 을 씁니다. `Esc`는 고른 핀 하나만 닫습니다. 저장한 파일은 바탕화면의 `다있쌤-핀-…png`이며, 클립보드 도우미가 다시 가져가지 않도록 캡처(`다있쌤-캡처-…png`)와 이름을 나눠 두었습니다.

### 확대·집중 모드와의 관계

두 기능이 서로를 망가뜨리지 않도록 정한 약속입니다.

- **macOS**: 핀 창과 조각 내기 화면은 발표 오버레이와 같은 `sharingType = .none`을 씁니다. 화면 캡처에 잡히지 않으므로 확대 화면 안에 핀이 한 번 더 겹쳐 그려지거나 스스로를 찍는 되먹임(v0.5.2의 재캡처 증상)이 생기지 않습니다. 창 레벨은 발표 오버레이보다 위(`screenSaver + 2`, 조각 화면은 `+ 3`)라 확대·집중 모드 중에도 원래 크기 그대로 또렷하게 남습니다.
- **Windows**: `MagSetFullscreenTransform`은 바탕화면 전체를 키우므로 핀도 함께 커집니다. 큰 포인터가 `1/zoom`으로 그리는 것과 같은 방식으로, 핀의 실제 크기와 위치를 배율만큼 보정해(`PinForm.Place`) 화면에 보이는 크기와 자리를 일정하게 유지합니다. 다만 OS가 화면 픽셀을 키우는 것이라 확대 중에는 핀도 함께 흐려집니다. 집중 모드의 어둡기 창보다 위로 올립니다(`RaisePins`).
- **조각을 내는 동안**에는 배율을 잠시 1배로, 집중 모드를 잠시 끕니다. 확대 중에는 눈에 보이는 자리와 실제 화면 좌표가 어긋나 엉뚱한 곳이 잘리기 때문입니다. 끝나면 원래 배율과 집중 모드로 되돌립니다.
- 조각 그림에는 기존 핀과 발표 표시(포인터 원·어둡기)가 들어가지 않습니다. macOS는 캡처 제외로, Windows는 화면을 그대로 복사하는 방식이라 잠시 감추는 방법으로 처리합니다.
- **키 우선순위**: 조각 내는 중이면 입력 감시가 아무 것도 가로채지 않고 그 화면이 `Esc`로 취소합니다. 핀을 고른 상태의 `Esc`는 그 핀만 닫습니다. 그 밖에는 기존대로 확대·집중 모드 해제 → 한 번 더 누르면 발표 종료입니다.
- **휠**은 겹치지 않습니다. 발표 확대는 `Control + Option/Alt + 휠`만 가로채고, 아무 조합 없는 휠과 `Command/Ctrl + 휠`은 핀으로 갑니다.
- 단축키는 발표 중에만 듣습니다. 입력 감시(macOS 이벤트 탭 · Windows 훅)를 발표 시작과 함께 켜기 때문이며, 발표 전에 켜면 손쉬운 사용 권한을 앱 실행만으로 요구하게 되므로 그렇게 하지 않았습니다.
- macOS 13에서는 조각 잘라내기를 쓸 수 없습니다(`SCScreenshotManager`가 macOS 14부터입니다). 클립보드 붙이기는 13에서도 됩니다.

## macOS

macOS 13 이상. ScreenCaptureKit의 라이브 스트림에서 자기 앱을 제외해 화면 확대가 다시 캡처되는 현상을 방지합니다. 마우스가 있는 디스플레이에서 시작합니다. 다른 모니터로 이동하면 확대 화면을 숨기고 기본 커서를 표시합니다. 다른 모니터에서 확대하려면 종료 후 해당 모니터에서 다시 시작합니다.

화면 기록과 손쉬운 사용 권한은 사용자가 직접 허용합니다. 허용 직후 시작이 실패하면 앱을 종료하고 다시 여세요. 메뉴 막대 앱이므로 Dock 아이콘은 없습니다. 개발용 임시 서명 빌드는 공증된 공개 배포본이 아닙니다. OS 보안 경고를 자동으로 우회하는 설치 스크립트는 제공하지 않습니다.

## Windows

Windows 10/11 x64. Windows Magnification API가 살아 있는 데스크톱을 확대합니다. 이 버전은 **기본 디스플레이**를 대상으로 합니다. 다른 모니터로 이동하면 기본 배율과 커서를 복원합니다. Windows ARM64는 검증/지원 대상으로 표시하지 않습니다.

제공된 `Presenter.exe`는 런타임이 포함되어 있으며 바로 실행할 수 있습니다. `Install.cmd`는 현재 사용자에게 앱 주소 연결을 등록합니다. `Uninstall.cmd`는 연결만 해제합니다. 앱 파일은 발표 종료 후 `%LOCALAPPDATA%\BrowserSheriff`에서 직접 삭제할 수 있습니다.

발표나 핀이 듣지 않으면 `Check.cmd`를 실행하세요. 설치·등록·앱 실행 여부와 **이 화면에서 확대가 되는지**를 차례로 재어 어디서 막히는지 알려 주고, 바탕화면에 `다있쌤-점검.txt`로 남깁니다. 가상 머신(VMware·Parallels 등)의 화면 드라이버는 Windows 확대 API를 지원하지 않는 경우가 많습니다. 그때는 **발표(확대)만 막히고 화면 조각 핀은 정상**입니다. VMware라면 설정에서 3D 그래픽 가속을 켜 보세요.

Windows 돋보기가 이미 확대 중이면 먼저 종료해 주세요. 앱 비정상 종료 후 확대가 남으면 실행 중인 발표 도우미를 종료한 다음 `Reset.cmd`로 기본 배율과 커서를 복원할 수 있습니다. 설정 값을 영구 변경하지 않습니다.

소스에서 빌드할 때는 .NET SDK 8의 `dotnet publish`를 권장합니다. `Build.cmd`는 Windows 기본 .NET Framework 4.x 컴파일러를 사용하는 대안이며 현재 환경에서는 그 대안 빌드를 실행하지 않았습니다.

## 실기기 확인 필요

Mac 화면 기록·전역 입력 권한, Windows 실제 실행, 화면 조각 핀(잘라내기·붙이기·이동·확대·투명도·클릭 통과·저장·모퉁이 잘라내기·조각 위에 그리기, 확대/집중 모드와 겹칠 때의 동작), Intel Mac 실행, DPI/다중 모니터, 전체 화면 앱, 영상 재생, 확대 중 클릭 위치, 절전/화면 잠금 시 복원, 화면 공유 수신자에게 보이는 확대와 포인터는 실기기 검증이 필요합니다. Mac/Windows 빌드 성공만으로 이 항목들을 통과 처리하지 않았습니다. 서명·공증·설치 프로그램을 통한 공개 배포는 별도 작업입니다.
